01 / THE PROCESS

From words to an address

An Ethereum wallet combines several cryptographic techniques. Each stage transforms information for a different purpose.

01 BIP-39

Mnemonic

Human-readable recovery words generated from entropy.

02 BIP-39

Seed

512-bit seed produced using PBKDF2-HMAC-SHA512.

03 BIP-32 / 44

Private Key

A child key derived from the HD wallet structure.

04 secp256k1

Public Key

Calculated by elliptic-curve multiplication Q = kG.

05 Keccak-256

Address

The final 20 bytes of the public-key hash.

06 EIP-55

Checksum

Mixed-case encoding helps detect typing errors.

Why not just one algorithm?

Key management, public-key cryptography, hashing and error detection solve different problems. Combining specialized techniques makes the wallet practical.

02 / THE TECHNOLOGY

Six pieces of the puzzle

These standards and primitives work together, but they are not interchangeable.

01RECOVERY

BIP-39

Converts random entropy into a mnemonic sentence. The sentence and an optional passphrase are processed with PBKDF2-HMAC-SHA512 to produce a 512-bit seed.

128-bit entropy → 12 words (typically)
02DERIVATION

BIP-32

Creates a hierarchical deterministic wallet. A master private key and chain code allow many child keys to be derived reproducibly from one seed.

One seed → multiple related keys
03ORGANIZATION

BIP-44

Defines a common five-level derivation path, separating purposes, cryptocurrencies, accounts, change branches and address indexes.

m/44'/60'/0'/0/0
04PUBLIC KEY

secp256k1

An elliptic curve used to calculate a public key from a private scalar. It also supports the digital signatures used to authorize transactions.

Q = kG
05HASHING

Keccak-256

Produces a 256-bit digest. Ethereum hashes the uncompressed public-key coordinates and takes the last 20 bytes to form an address.

256-bit hash → 160-bit address
06ERROR DETECTION

EIP-55

Uses the hash of a lowercase hexadecimal address to determine which alphabetic characters should appear in uppercase.

Same address, mixed-case representation

06 / ADDRESS CHECKSUM

Can a typo be detected?

EIP-55 introduces mixed-case encoding to help identify accidental errors in Ethereum addresses.

Press Validate Address to check the example.

EIP-55 does not encrypt an address or prevent every possible error. It provides additional error detection. All-lowercase and all-uppercase addresses are also accepted by many Ethereum tools.

07 / HISTORICAL CONTEXT

How did we get here?

Modern wallets combine ideas developed across several decades of cryptographic research.

1977

RSA

Public-key cryptography based on integer factorization.

2001

SHA-2 / SHA-512

A new family of standardized cryptographic hash functions.

2012

BIP-32

Hierarchical deterministic key derivation.

2013

BIP-39

Mnemonic phrases for deterministic wallets.

2014

BIP-44

Standardized multi-account derivation paths.

2015

SHA-3

NIST standard based on the Keccak design.

2016

EIP-55

Mixed-case checksum encoding for Ethereum addresses.

SHA-512, Keccak-256 and SHA3-256

SHA-512

Part of SHA-2. Produces a 512-bit digest. Used inside HMAC-SHA512 and PBKDF2 in wallet derivation.

Keccak-256

Produces 256 bits and is used in Ethereum address derivation. It uses the original Keccak padding convention.

SHA3-256

Standardized by NIST in 2015. Based on Keccak, but uses different domain-separation padding, so the digests differ.
